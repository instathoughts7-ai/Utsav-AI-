## 🌟 About the Project

**Utsav AI — Your Celebration, Perfectly Planned** is a Generative AI-powered event-planning application designed to simplify the process of organizing weddings, birthdays, and community celebrations.

Planning an event involves managing multiple interconnected decisions: budgets, guest lists, venues, catering, decorations, schedules, vendors, cultural traditions, and unexpected changes. Utsav AI brings these planning activities together in one structured workflow.

Users can generate personalized event blueprints, review budget allocations, explore alternative scenarios, manage planning milestones, prepare vendor checklists, and export their plans for future reference.

The application combines the contextual capabilities of Google's Gemini AI with deterministic TypeScript calculations to help users make informed planning decisions.

### 🎯 Our Vision

Make event planning more accessible, organized, personalized, and financially transparent by combining artificial intelligence with practical planning tools.

## ❗ Problem Statement

Organizing a successful celebration can be complicated, time-consuming, and expensive.

Event organizers frequently face challenges such as:

- Planning an event within a fixed budget.
- Managing guest counts and changing requirements.
- Coordinating venues, catering, decorations, entertainment, and vendors.
- Creating a realistic event timeline.
- Incorporating cultural traditions and regional preferences.
- Identifying hidden expenses and maintaining contingency funds.
- Protecting important priorities when financial constraints change.
- Keeping event details organized in one place.

Traditional planning methods often require multiple spreadsheets, documents, conversations, and manual calculations.

When budgets or guest counts change, organizers may need to revise several parts of their plans manually.

### The core challenge

**How can AI help people create personalized event plans while keeping budgets, priorities, and practical constraints under control?**

Utsav AI addresses this challenge by combining AI-generated recommendations, structured event planning, deterministic budget calculations, and interactive scenario replanning.

## 💡 Our Solution

Utsav AI transforms event requirements into an actionable planning blueprint.

The application uses two complementary engines:

**1. Generative AI engine**

Google Gemini generates contextual recommendations for themes, menus, timelines, activities, vendor preparation, cultural considerations, and event-planning strategies.

**2. Deterministic calculation engine**

TypeScript application logic calculates budget allocations and related financial values, avoiding reliance on AI-generated arithmetic.

Together, these engines help users explore creative options while keeping the financial structure of a plan explicit.

### The user journey

1. Enter the event type, location, guest count, budget, and preferences.
2. Generate a personalized event blueprint.
3. Review budget categories and estimated costs.
4. Explore timelines, vendor checklists, activities, and regional recommendations.
5. Modify constraints and use What-If replanning.
6. Review revised allocations and protected priorities.
7. Track planning progress and expenses.
8. Export the plan as JSON or print it for reference.

## 🚀 Key Features

### 1. 🤖 AI-Powered Event Planning

Generate a structured event blueprint using the event details provided by the user.

The generated plan may include:

- Event themes and celebration concepts.
- Budget category recommendations.
- Event schedules and milestones.
- Regional menu and activity suggestions.
- Vendor checklists.
- Questions to ask vendors during negotiations.
- Practical reminders and risk-mitigation suggestions.

The objective is to turn a broad event idea into an organized starting point that the user can review and customize.

### 2. 💰 Smart Budget Management

Manage the financial structure of an event through a dedicated budget workflow.

Reported capabilities include:

- Total event budget.
- Category-wise budget allocations.
- Actual expenses and remaining funds.
- Cost-per-guest calculations.
- Contingency planning.
- Vendor-planning progress.
- Milestone progress tracking.

Budget calculations are handled by deterministic application logic rather than asking the language model to perform financial arithmetic.

This helps keep financial calculations consistent within the supported application workflows.

### 3. 🔄 What-If AI Replanner

Event requirements can change at any time.

The What-If Replanner helps users explore alternative plans when they modify constraints such as:

- Total budget.
- Number of guests.
- Planning strategy.
- Protected priorities.

The application can propose revised allocations and contextual recommendations based on the changed requirements.

Users can compare the revised plan with the existing plan and decide which changes to accept.

### 4. 🛡️ Priority Shielding

Not every part of an event should be reduced when a budget becomes tighter.

Priority Shielding is designed to preserve user-designated non-negotiable requirements during replanning.

Examples may include:

- Essential cultural rituals.
- Required catering arrangements.
- Important photography requirements.
- Other priorities explicitly marked as non-negotiable.

The application evaluates replanning scenarios with the intention of protecting these requirements while adjusting other areas where possible.

Users should always review the revised plan to confirm that their requirements remain satisfied.

### 5. 📅 Event Timelines and Milestones

Organize the event-planning process into manageable tasks and milestones.

The planning workflow can help users understand what needs to be prepared, what remains outstanding, and which activities should be coordinated before the celebration.

Milestone tracking makes it easier to monitor progress rather than relying entirely on memory or disconnected notes.

### 6. 🤝 Vendor Checklists and Negotiation Guidance

Prepare for vendor conversations using structured checklists and suggested questions.

The guidance can help organizers discuss requirements, compare proposals, clarify inclusions, and identify details that need confirmation.

Vendor recommendations and estimated prices are planning aids. They are not proof of availability, confirmed bookings, or guaranteed quotations.

### 7. 🌏 Cultural and Regional Personalization

Event planning often depends on regional preferences, traditions, food, and celebration styles.

Utsav AI can use the context provided by the user to generate more relevant recommendations for the event.

For example, a Maharashtrian wedding plan may require different rituals, menus, and scheduling considerations from a birthday celebration or a community festival.

The quality and accuracy of these recommendations depend on the information supplied and the AI response. Important cultural, dietary, and logistical details should be reviewed by the organizer.

## 🧠 How Generative AI Is Used

Utsav AI integrates the **Google Gemini API** through Google's `@google/genai` SDK.

### AI-assisted capabilities

| Capability | How AI contributes |
|---|---|
| Event blueprint generation | Creates contextual event-planning recommendations. |
| Theme suggestions | Proposes celebration concepts based on event details. |
| Timeline planning | Suggests a structured sequence of planning activities. |
| Regional menus and activities | Generates context-aware suggestions based on user preferences. |
| Vendor guidance | Creates checklists and questions for vendor discussions. |
| Risk mitigation | Suggests potential planning risks and practical precautions. |
| What-If explanations | Provides contextual reasoning for alternative planning scenarios. |

### Dual-engine design

The application separates generated recommendations from financial calculations.

**Generative AI** is used for contextual content and recommendations.

**Deterministic TypeScript logic** is used for budget calculations and related numerical operations.

This separation reduces reliance on generated text for financial calculations and makes the financial logic easier to test.

### AI reliability

AI responses can be incomplete, delayed, or invalid. The reported implementation includes response validation, timeout handling, and fallback behavior for selected failure scenarios.

AI-generated plans should be reviewed before being used to make financial commitments or operational decisions.

## 🔄 What-If AI Replanner

The What-If Replanner helps users understand how changing event requirements can affect a plan.

For example, an organizer may reduce the budget from ₹2,50,000 to ₹2,00,000 or change the guest count before the event.

The replanning workflow can propose adjustments to allocations and provide context for those adjustments.

### Replanning workflow

1. Start with an existing event plan.
2. Change the relevant budget, guest count, or strategy.
3. Request a revised plan.
4. Review the proposed changes.
5. Confirm that protected requirements remain satisfied.
6. Apply the revised plan only after reviewing it.

### Replanning safeguards

The latest supplied audit reports:
- Handling of zero-percent budget allocations.
- Preservation of protected priorities in tested replanning scenarios.
- Timeout handling for Gemini-based replanning enrichment.
- Fallback behavior when selected AI enrichment operations time out.

These safeguards are intended to make replanning more reliable while keeping the final decision with the user.

## 🛡️ Priority Shielding

Priority Shielding represents user-defined requirements that should not be casually removed during budget optimization.

For example, a user may decide that a particular ceremony or catering requirement must be preserved even if other allocations need to change.

The replanner uses these constraints when generating alternative scenarios.

The final result should always be reviewed. If the budget is too small to satisfy every protected requirement, the application should not be assumed to make the event financially feasible automatically.

## 🔐 Security and Privacy

Security is important because the application processes event details, planning information, and API requests.

The latest supplied audit reports the following controls.

### Server-side API key handling

- The Gemini client is intended to initialize on the server.
- The API key is read from `GEMINI_API_KEY`.
- The key must not be embedded in frontend code.
- Secrets must not be committed to GitHub.

### HTTP security headers

The report states that the following headers were verified in the local application:

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: SAMEORIGIN`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy` restricting camera, microphone, and geolocation access.

The report also states that Express `X-Powered-By` fingerprinting was disabled.

### Rate limiting

The audit reports a dedicated rate limit on the event-plan endpoint, with a configured ceiling of 10 requests per minute in the tested environment.

Rate limits and their behavior must be checked against the deployed configuration.

### Request validation

Reported safeguards include:

- Request payload-size limits.
- Validation of incoming data.
- Rejection of prohibited object keys in tested payloads.
- JSON import schema validation.
- AI response validation.
- Timeout handling and fallback behavior for selected failure scenarios.

### Dependency security

The latest supplied audit reported zero vulnerabilities from an `npm audit` run covering 199 packages.

This result reflects that audit at that time. Dependency security should be rechecked after package changes and before deployment.

### Privacy note

Do not enter sensitive personal, financial, or confidential information unless the application explicitly supports the intended handling and you understand the applicable privacy practices.

Security checks performed locally do not automatically prove that the public deployment has identical controls.
